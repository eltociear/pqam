# AP2 PQC v1: an independent implementation and cross-implementor cases

For [AP2 #250](https://github.com/google-agentic-commerce/AP2/issues/250) and
[chopmob-cloud/ap2-pq-conformance](https://github.com/chopmob-cloud/ap2-pq-conformance). This is **their** v1 construction, not
pqam's own format:

```
signed_input = "AP2PQC/1.0/" + object_type + 0x00 + JCS(mandate_body) + 0x00 + JCS(signer_set)
```

- `ap2pqc-v1.mjs` is a JavaScript implementation written from their README and `verify_v1.py`. It shares no code with
  theirs, and has its own JCS, ES256 (P-256, DER), Ed25519, ML-DSA-65 and Falcon-1024 (noble). It applies the same
  fail-closed rules.
- **Against their fixture** (`upstream/`, copied unchanged): it reproduces the 501 JCS bytes exactly, and all three
  signatures in `ap2-pqc-v1-algovoi-side.json` (ES256, Ed25519, Falcon-1024) verify. The v0 fixture is refused under the
  v1 rules.
- **`pqam-cross-v1.json`**: 18 cases generated by this implementation over their `mandate_body`, with keys from published
  seeds and deterministic signatures, so the file is byte-reproducible (`node build-cases.mjs`).
  - Group A, ES256 + Ed25519 (runnable by `verify_v1.py` today): valid, both stripping directions, strip plus descriptor
    rewrite, object-type relabel, key_id mismatch, an unlisted extra signer, an unknown algorithm, an edited body.
  - Group B, ES256 + ML-DSA-65: the same nine cases for the post-quantum hybrid. A verifier without ML-DSA-65 fails
    closed on all of them, as recorded per case.

Every case was checked by this implementation only. We have not run their Python verifier on them; running it is
the point of handing the file over.
